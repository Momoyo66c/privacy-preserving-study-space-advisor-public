## D-010：真实雷达端口必须显式指定

- 日期：2026-07-18
- 状态：生效
- 决策：`config/real.example.yaml` 从 `RADAR_PORT` 读取 LD2450 串口，未设置时拒绝加载；优先使用 `/dev/serial/by-id/` 稳定路径。模拟配置使用明确的未使用占位值。

- 日期：2026-07-18

## D-015：ESP32 作为可选多传感器串口 Hub

- 日期：2026-07-20
- 状态：架构生效，传感器选型被 D-018 更新
- 决策：保留现有 Raspberry Pi 直连驱动，同时增加 `esp32_hub` 传输模式。ESP32 通过一条 USB 串口复用五类传感器消息；Pi 端兼容适配器继续实现现有 `SensorDriver`，不改变模块 1 窗口和跨模块 Schema。串口采用 COBS、CRC32、全局序号和有界负载。
- 原因：用户希望实际使用现有 ESP32，但不接受大范围架构重构。传输适配层可以隔离物理接线变化，保留窗口、存储、隐私和模块 2 接口。直连模式提供回退和对照。
- 限制：经典 ESP32-D0WD-V3 不能直接作为普通 USB 麦克风的 USB Host。全部传感器经 Hub 时应使用 I2S 麦克风；保留 USB 麦克风时，声音仍由 Raspberry Pi 直连驱动读取。

## D-016：Sensor Hub 固件采用固定依赖和二进制串口输出

- 日期：2026-07-20
- 状态：被 D-018 部分取代
- 决策：`sketch.yaml` 固定 ESP32 core 3.3.10、Adafruit AHTX0 2.0.6、BusIO 1.17.4、MLX90640 1.1.2 和 Unified Sensor 1.1.15。固件只在主机串口发送 COBS/CRC32 协议帧，不输出文本日志；I2S 声音只生成 RMS、标准差和峰值，默认在实物接入前关闭。开机缺失的可重试设备每 5 秒重新初始化。
- 原因：固定 profile 使 Raspberry Pi 构建可复现；禁止混入文本可避免破坏帧边界；不传输原始音频维持模块 01 的隐私边界；周期重试允许后接传感器而无需重烧固件。
- 许可证：构建依赖为 BSD-3-Clause、MIT 或 Apache-2.0，精确版本、来源、许可证哈希和必要通知记录在 `edge/hardware/THIRD_PARTY_NOTICES.md`。项目根许可证仍由团队另行决定。

## D-017：连接边界不得复用旧样本或旧能力状态

- 日期：2026-07-20
- 状态：生效
- 决策：ESP32 USB 断开、共享 Hub 最后一个客户端关闭或检测到设备重启时，立即清空所有传感器队列、能力位、远端健康状态和设备丢样计数。序号与 uptime 诊断保留到新帧到达，用于识别设备重启；重新收到心跳前不沿用旧能力。
- 原因：传感器样本只在连接和设备会话内有效。把断开前队列交给重连后的窗口会制造“当前采集成功”的假象，破坏健康状态和时间语义。
- 验证：USB 故障后旧/新光照帧隔离、能力撤销、远端离线、序号乱序、双回退重启和关闭幂等测试均通过。

## D-018：按实际四传感器型号升级 Hub 协议 v2

- 日期：2026-07-20
- 状态：生效
- 硬件：控制板为 WeMos D1 R32。HW-507/DHT11 数据接 GPIO27；HW-485 AO 经 10 kΩ/10 kΩ 分压接 GPIO34；HW-486 S 接 GPIO35；MLX90640 SDA/SCL 接 GPIO21/22。所有模块共地。LD2450 在到货前保持关闭。
- 决策：以 DHT11 替代 AHTX0，以 HW-485 ADC 相对统计替代 I2S 声音，以 HW-486 ADC 代理值替代 BH1750 lux；MLX90640 热帧格式不变。DHT11 读取间隔固定为 2 秒，HW-485 原始 ADC 只短暂存在 RAM，串口仍只传 RMS、标准差和峰值。
- 光照语义：HW-486 未标定时必须产生 `light_lux=null`、`calibrated_lux=false` 和 `hw486_uncalibrated_light_proxy`。协议保留显式标定标志，只有该标志有效时才接受 lux。
- 兼容性：`LIGHT` 负载从单个 lux 浮点改为 ADC、归一化值、可选标定 lux 和 flags，因此协议版本从 1 升为 2；v2 主机必须拒绝 v1 帧，固件和 Pi 适配器必须成对部署。
- 许可证：固定依赖改为 DHT sensor library 1.4.6（MIT），移除 AHTX0；许可证哈希和通知记录在 `edge/hardware/THIRD_PARTY_NOTICES.md`。

## D-019：HW-485 安静窗口不能作为掉线依据

- 日期：2026-07-20
- 状态：生效
- 现场证据：聚合诊断确认该批 HW-485 的 AO 静音窗口为 0，制造声音时 GPIO34 峰值从 0 上升到 230/192，并在后续试验中再次升到 27/21。用低峰峰值或零均值判断掉线都会误杀真实静音。
- 决策：删除所有基于窗口幅度的掉线判定。静音全零窗口作为有效相对声级上报；RMS、标准差和峰值仍在 ESP32 本地计算。
- 边界：普通模拟输入无法仅凭零电平区分“正常安静”和“接地/断线”。首次部署必须完成有声响应试验和分压检查；原始 ADC 样本仍只存在 ESP32 RAM，不经串口传输或落盘。
