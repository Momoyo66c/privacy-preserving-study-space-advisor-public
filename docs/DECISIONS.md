# 决策记录

## D-001：本阶段采用单主 Agent 串行执行

- 日期：2026-07-18
- 状态：生效
- 决策：只由当前主 Agent 执行，不创建子任务，不并行处理。唯一自动任务每 2 小时触发一次，并在开始修改前检查是否存在其他活动任务或新修改。
- 原因：减少重复开发、交叉覆盖和来源不明的提交。

## D-002：保留并隔离未确认的参考源码

- 日期：2026-07-18
- 状态：生效
- 决策：在完成远端、固定提交、用途和许可证审计前，不删除、不移动、不整批提交 `references/`，也不复制其中代码到产品目录。
- 原因：这些目录可能由其他 Codex 任务留下；仓库完整性和复用条件尚未确认。

## D-003：以三层视图组织当前骨架核验

- 日期：2026-07-18
- 状态：生效
- 决策：不改变现有四模块规格，只在项目骨架层面采用三层视图：`edge/` 为采集与边缘层，`backend/` 加 `shared/` 为服务与数据层，`frontend/` 为展示层；`tests/integration/` 负责跨层验证。
- 原因：三层视图与现有四模块职责兼容，无需搬迁已完成代码或提前实现后续模块。

## D-004：冻结完整 ML、LLM 和 Dashboard 实现

- 日期：2026-07-18
- 状态：生效
- 决策：本阶段只建立或核验目录、入口说明、共享契约边界和最小测试入口，不实现完整 ML 流程、大模型调用或 Dashboard。
- 原因：避免越过当前阶段范围，并保持提交可审阅。

## D-005：树莓派连接作为继续执行门禁

- 日期：2026-07-18
- 状态：生效
- 决策：继续执行前先尝试 SSH 重连。连续重试仍失败时，停止当前后续阶段并停用自动任务。
- 原因：用户明确要求连接失败时取消后续所有任务。

## D-006：GPL 与 AGPL 参考仓库只作对照

- 日期：2026-07-18
- 状态：生效
- 决策：`IoTProject-ZonePresenceDetection-LD2450`、`crowdaware-node` 和 `PiThermalCam` 只用于协议、部署和架构对照，不复制其实现代码。
- 原因：前两者为 GPLv3，后者为 AGPLv3；当前项目没有根许可证，不能先假定分发兼容。

- 决策：本阶段记录根许可证缺失，但不代替项目负责人添加或选择许可证。MIT 依赖继续保留版权与许可声明。
